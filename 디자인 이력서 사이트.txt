나는 웹디자이너이고 웹에이전시 지원용 디자인이력서를 사이트 형태로 만들려고 해
mini_resume 이라는 프로젝트 디렉토리에서 아래의 내용대로 구현해줘
Supabase MCP를 사용해서  portfolio폴더에 다른 프로젝트와 구별하여 데이터베이스를 구축하고,
모든 개발이 완료되면 GitHub Pages로 최종 배포까지 진행해줘.
GitHub Actions 워크플로우를 사용해서 자동 배포되도록 설정하고, 배포 완료 후 접속 가능한 URL을 안내해줘.
url은 관리용과 게시용(제출용)으로 따로 추출해줘
디자인 및 이미지는 폴더 asset부분과 클로드다지인에서 추출한 파일을 참고해줘

[기획 및 디자인]

1. 주제
웹디자이너 지원용 포트폴리오 겸 디자인 이력서 사이트

2. 목적
-이력서를 사이트 형태로 구현하여 움직임을 넣어서 새로운 방식으로 지원하므로써 나의 정보 뿐만 아니라 감각 및 역량 보여주기
-url형태로 이력서를 제출하여 보다 많은 사람들이 나의 이력서를 볼 수 있도록
-단순히 이력서를 지원하고 끝나는 것이 아니라 이력서를 본 회사에서 댓글 등의 코멘트 작성 및 면접요청 등의 기능을 통하여
  나의 포트폴리오 성장을 돕고 양방향적 소통이 가능하도록 함

5. 컨셉
핵심 키워드 - 빨강 / 사과 / 통통튐 
디자인 방향 - 스크롤시 좌우로 이동하여 스토리라인을 보여주는 형태의 풀페이지 사이트로
                         각 페이지별 이력서 내용을 담아냄

6. 콘텐츠 내용(부분별 들어갈 내용 및 대략적인 배치)
타이틀 : 디자인 이력서 타이틀 보여지는 부분 -> 제목 부분의 텍스트가 자동으로 움직임이 있도록(bobbing and floating animation)
콘텐츠1 : 나의 이미지 및 간단한 이력사항 보여줄 페이지 -> 가운데 나의 이미지를 배치하고 카카오톡 같은 메신저 알림창이 뜨듯이 하나씩 보여주기 
콘텐츠2 : About me 페이지 - 나의 프로젝트 참여 예시 이미지와 나의 강점 등을 보여줄 수 있는 페이지
콘텐츠3 : QnA - 스스로 질문하고 답하여 나에 대한 부분을 더 보여줄 수 있도록
: 가운데 입력창 - 이력서를 열람한 사람이 의견을 남기는 공간 -> 이미지,텍스트 업로드를 하면 회사별 코멘트를 같이 볼 수 있고 / 면접요청을 누르면 전화번호 / 이메일주소 복사하게
콘텐츠4 : 코멘트 리스트 페이지 -> 여러 사람이 올려둔 질문 및 의견을 모아볼 수 있도록 하며 카드형태로 배치 (5*2)
푸터 : contact me 부분 - 이력서를 본 다양한 사람들이 의견을 남길 수 있도록 하고 바로 이메일 쓰기, 연락하기 등이 가능하도록 함 / 푸터 부분에서 내용을 입력하면 4콘텐츠 부분에 카드형태로 뜨고 카드를 누르면 팝업창으로 더 자세한 내용을 보고
답글 등을 달 수 있도록!

4. DB 구조 설계(예시 테이블)

1)user테이블

-id | UUID / INT | PK, Auto Increment |고유 유저 ID
-email | VARCHAR | UNIQUE, NOT NULL | 이메일 (로그인용)
-password | VARCHAR | NOT NULL | 암호화된 비밀번호
-role | VARCHAR | DEFAULT 'user' | 권한 (admin, user 구분)
-created_at | TIMESTAMP | DEFAULT NOW() | 계정 생성일

2)comments테이블

id | INT / UUID | PK, Auto Increment | 코멘트 고유 ID
parent_id | INT / UUID | FK (Self-referencing), NULL 허용 | 답변용 필드: 원본 질문의 id를 가리킴 (질문글이면 NULL)
author_name | VARCHAR | DEFAULT '익명' | 작성자 이름 (입력 안 하면 익명)
content | TEXT | NOT NULL | 코멘트/답변 본문 내용

5. DB설계 주의사항
1) 코멘트 답변 기능 (parent_id 활용법)
사용자가 질문을 남기면 parent_id는 NULL 상태로 저장
관리자가 팝업창에서 답변을 작성하면, 새로운 행(Row)이 추가되되, parent_id에 원본 질문의 id를 매핑

프론트엔드(Claude Code) 구현 : 코멘트 리스트를 불러올 때 where parent_id IS NULL인 것들만 카드(5*2)로 먼저 뿌려주고,
카드를 클릭해 팝업이 뜨면 해당 id를 parent_id로 가진 답변 데이터가 있는지 다시 조회(Select)

2)관리자 기능 (삭제 및 비공개 처리)
데이터 실제 삭제(DELETE)보다는 Soft Delete 권한 부여 :  is_deleted = TRUE로 상태만 변경하고, 사용자 화면에서는 where is_deleted = FALSE 조건으로 필터링해 보여주지 않는 방식

비공개 기능: is_private = TRUE인 카드는 사용자 화면에서 블러(Blur) 처리를 하거나 "관리자에 의해 비공개 처리된 글입니다"라는 안내 문구만 띄우도록 분기 처리

3)이미지 파일 업로드 관련
DB 테이블의 image_url 필드에는 이미지 파일 자체가 저장되는 것이 아니라, 이미지가 저장된 스토리지(e.g., AWS S3, Supabase Storage, 혹은 로컬 서버 폴더)의 주소 문자열이 저장
'이미지 업로드 API -> 반환된 URL을 DB의 image_url에 저장'하는 2단계 프로세스로 기획

6. 화면과 DB 테이블의 연결 구조
1) 사용자 화면: [코멘트 입력창] 및 [카드 리스트(5*2)]
사용자가 코멘트를 등록 : * 사용자가 푸터에서 텍스트와 이미지를 넣고 완료를 누르면, Comments 테이블에 새로운 행(Row)이 하나 생성
이때 질문글이므로 parent_id는 빈칸(NULL)으로 저장

화면에 카드 리스트를 불러올 때:
DB에서 where parent_id IS NULL(답변이 아닌 원본 질문만)인 데이터를 최신순으로 10개(5*2) 가져와서 카드 형태로 화면에 띄우기
image_url 값이 있으면 이미지+텍스트 카드로, 없으면 텍스트만 있는 카드로 분기 처리

2)사용자/관리자 화면: 코멘트 클릭 시 뜨는 [상세 팝업창]
팝업창을 열었을 때: 특정 코멘트 카드를 클릭하면, 그 카드의 고유 ID(id)를 가지고 팝업창이 열리도록
이 팝업창 안에서는 두 가지 데이터를 Comments 테이블에서 조회하여 보여주기
클릭한 원본 질문 내용: where id = 클릭한ID
관리자가 달아놓은 답변 내용: where parent_id = 클릭한ID

3. 관리자 화면: [답변 작성 기능]
관리자가 팝업창에서 답장을 쓰고 완료를 누를 때:
새로운 테이블을 만드는 것이 아니라, 똑같이 Comments 테이블에 새로운 행(Row)을 추가(Insert)
단, 이때는 관리자가 쓴 글이므로 parent_id에 방금 클릭해서 들어온 원본 질문의 id 번호를 적어서 저장합니다.
